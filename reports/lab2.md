## 实现总结

重写了 `sys_get_time` 和 `sys_trace`：前者将 `TimeVal` 通过 `translated_byte_buffer` 写入用户地址空间，能跨页。
后者按 `trace_request` 在当前任务页表上查 PTE，要求加对应的 `R/W` 才读写，否则返回 -1。request=2 时返回每任务 syscall 调用次数。
实现了 `sys_mmap/sys_munmap`：校验 start 对齐、prot 合法位后，在 `MemorySet` 上新增 `mmap`/`munmap` 方法，mmap 前遍历 VPN 区间确认均未映射再 push 一个 Framed `MapArea`，munmap 前确认均已映射后从各 `MapArea.data_frames` 中移除对应 FrameTracker（随 drop 自动归还物理页帧）并在页表里 unmap。syscall 计数由 syscall 分发入口统一 `+1`。

## 问答题

### 1. SV39 页表项的组成

SV39 的每个 PTE 共 64 位，结构（高位 → 低位）如下：

| 位段 | 名称 | 作用 |
|---|---|---|
| [63:54] | Reserved | 保留，必须为 0 |
| [53:28] | PPN[2] | 物理页号高位（26 位） |
| [27:19] | PPN[1] | 物理页号中位（9 位） |
| [18:10] | PPN[0] | 物理页号低位（9 位） |
| [9:8] | RSW | 供 S 态 OS 自由使用的两位，硬件忽略 |
| [7] | D (Dirty) | 页被写过 |
| [6] | A (Accessed) | 页被读/写/取指过 |
| [5] | G (Global) | 全局映射，TLB 跨 ASID 共用 |
| [4] | U (User) | U-mode 是否可访问该页 |
| [3] | X (eXecutable) | 可执行（取指） |
| [2] | W (Writable) | 可写 |
| [1] | R (Readable) | 可读 |
| [0] | V (Valid) | PTE 是否有效 |

说明几点：

- `V=0` 时该 PTE 无效，访问会触发缺页；`V=1` 且 `R=W=X=0` 表示这是一个**指向下级页表**的非叶 PTE。
- `U` 位决定权限分区：U=1 的页默认只允许 U-mode 访问，S-mode 需要置 `sstatus.SUM` 才能访问；U=0 的页 U-mode 永远不可访问。
- `A/D` 位用于让 OS 做页替换/写回的统计（本实验未使用）。
- `G` 位标记跨进程不变的全局映射（如内核区段），TLB 不会因 ASID 切换而失效。

### 2. 缺页

#### 2.1 哪些异常可能是缺页导致的？

RISC-V 里有三种 Page Fault 异常：

- **Instruction Page Fault** (scause=12)：取指时地址翻译失败。
- **Load Page Fault** (scause=13)：load 指令访问的地址翻译失败。
- **Store/AMO Page Fault** (scause=15)：store 或 AMO 指令访问的地址翻译失败。

"翻译失败"包括：PTE `V=0`、对应权限位（R/W/X）不满足、U/S 权限不匹配（U 位与当前特权级冲突）等。

#### 2.2 缺页时相关寄存器

- `scause`：异常号，分别为 12 / 13 / 15。
- `stval`：**触发缺页的虚拟地址**（这个是缺页场景独有的关键值，用于定位到底是哪一页）。
- `sepc`：触发缺页的那条指令的 PC。
- `sstatus`：其中的 `SPP` 指示发生异常前的特权级，`SPIE` 保存了异常前的 `SIE`。
- `stvec`：异常入口（指向 `__alltraps`）。

#### 2.3 Lazy 策略的好处

- **启动快**：无需在加载时一次性建立全部映射与读入全部数据，`exec` 立即能返回。
- **省内存**：从未访问到的代码/数据不占物理页（例如大量从未走到的错误分支、未用到的库函数）。
- **省磁盘 I/O**：延迟到真正需要时再从磁盘加载，很多页可能根本不需要。
- **与 COW 配合**：`fork` 后父子共享物理页，仅在真正写入时才复制，省掉大量多余拷贝。
- **灵活性**：可以支持比物理内存更大的虚拟地址空间请求（例如 `mmap` 一块 10 GB），因为背后的物理资源按需分配。

#### 2.4 10 GB 连续内存的 SV39 页表开销

对 10 GB 连续映射：
- 叶页表（L0）：10 GB / (4KB * 512) = 5120 张，**5120 * 4KB = 20 MB**。
- 中间页表（L1）：5120 / 512 = 10 张，**10 * 4KB = 40 KB**。
- 根页表（L2）：1 张，4 KB。

合计约 **20 MB** 的数量级。

#### 2.5 如何实现 Lazy mmap

- `sys_mmap` 时**只记录** `[start, start+len)` 以及对应的权限、类型（匿名/文件映射），**不**分配物理帧、也**不**建叶 PTE；可以在 `MemorySet` 中新增一个"待分配区域"列表（lazy MapArea）。
- 缺页处理：trap 进入 S-mode 后，取 `scause` + `stval`，检查 `stval` 是否落在某个 lazy 区域内：
  - 若是：`frame_alloc` 一个物理页，按权限建立 PTE，`sfence.vma` 后返回异常指令（`sepc` 不动，重新执行）。
  - 若否：这是真正的非法访问，杀掉进程。
- `munmap` 时只需移除该区域的记录；对已经被访问过、已有 PTE 的页，走正常 unmap 回收物理帧即可。

#### 2.6 swap 后 PTE 的表现

把物理页换出到磁盘后，OS 会把该 PTE 的 `V` 位清 0。这样下次访问会触发缺页，OS 在缺页处理中再把它换回来。

### 3. 双页表与单页表

#### 3.1 单页表情况下，如何更换页表？

每次切换进程/线程时，将新进程的根页表 PPN 写入 `satp`，再执行 `sfence.vma` 刷 TLB。由于用户区和内核区都在同一张表里，这是用户/内核**共享**的一次切换，陷入内核态时**不需要**换 `satp`。

#### 3.2 如何保证用户态访问不到内核页面？

依靠 PTE 的 **U 位**：内核映射的 PTE 都置 `U=0`，U-mode CPU 访问 U=0 的页会立刻触发 page fault。进入 S-mode 后要访问用户页，默认也是禁止的，需要设 `sstatus.SUM=1` 临时允许（或走软件拷贝的路径）。

#### 3.3 单页表有何优势

- **陷入/返回快**：syscall、trap 时不用换 `satp`、不用 `sfence.vma`、不用维护 trampoline，TLB 也不失效，开销小。
- **内核访问用户地址方便**：开 `SUM` 后可直接按用户虚拟地址读写，不用像双页表那样 `translated_byte_buffer` 逐页翻译+拷贝。
- **TLB 利用率高**：内核那部分映射全局共享（可用 `G` 位），切用户进程时内核部分 TLB 项仍然命中。
- **实现简单**：trampoline、双份映射这些工程复杂度都省了。

代价是容易暴露于侧信道攻击（Meltdown 类）：用户态在 U=0 页上的推测执行仍能影响 CPU 微架构状态，KPTI 为此才改用双页表隔离。

#### 3.4 何时更换页表

- **双页表（当前 rCore）**：在 trampoline 里，用户态 → 内核态时把 `satp` 从用户页表切到内核页表；内核态 → 用户态（`__restore`）时切回用户页表。此外，任务调度切到另一个进程时，由于每个进程有独立的用户页表，`__restore` 时写入的就是新进程的 `satp`，相当于进程切换也在此完成。

- **单页表设计**：只在**进程切换**时换页表——即把 `satp` 改成目标进程的根页表。Trap / syscall 由于共用一张表不必换表。中断/异常内也无需换表。这样可以把换表与 TLB 刷新集中到真正必要的那一个时间点。
